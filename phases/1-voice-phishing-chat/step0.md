# Step 0: docs-update

## 읽어야 할 파일

먼저 아래 파일들을 읽고 프로젝트의 아키텍처와 설계 의도를 파악하라:

- `/CLAUDE.md`
- `/docs/PRD.md`
- `/docs/ARCHITECTURE.md`
- `/docs/ADR.md`
- `/docs/UI_GUIDE.md`

이 step은 코드를 전혀 건드리지 않는다. 뒤이은 step1(콘텐츠)·step2(채팅 UI 구현)가 참조할 설계 결정을 문서에 먼저 확정해 두는 것이 목적이다. 아래 배경을 이해하고 작업하라:

보이스피싱 체험만 채팅형 UI(참고: [javiow/sache](https://github.com/javiow/sache) 레포의 `ChatBubble`/`TypingIndicator`/`ChatChoiceButtons` 패턴 — 타이핑 인디케이터 + 메시지별 딜레이 후 말풍선 등장, 선택지 클릭 즉시 진행, 별도 "다음"/전송 버튼 없음)로 재설계한다. 사례선택/전세매물 두 유형은 기존 "선택 후 다음 버튼 클릭" 방식을 그대로 유지한다 — 이 둘은 이번 변경 대상이 아니다.

또한 기존 코드에서 보이스피싱 채점 로직의 버그를 발견했다: 오답 사유가 "정상 케이스인데 거절"이든 "사기 케이스인데 응함"이든 상관없이 `mistakeTag`가 항상 `"blind-refusal"`로 동일하게 찍힌다. 이번에 `"fell-for-scam"`(사기에 응한 경우 전용) 태그를 신설해 구분한다. 이 문서 step에서는 그 사실을 `ARCHITECTURE.md`에 기록만 하고, 실제 코드 수정은 step2에서 한다.

## 작업

아래 3개 문서를 정확히 다음 내용으로 수정한다. 문구를 크게 바꾸지 말고 명시된 변경만 반영하라 — 이 문서들은 팀원 여러 명이 참조하는 합의된 설계 기록이다.

### 1. `docs/ADR.md`

기존 ADR-005 다음에 새 ADR을 추가한다:

```markdown
### ADR-006: 보이스피싱만 채팅형 UI로 전환, 나머지 유형은 기존 "다음" 버튼 유지
**결정**: 보이스피싱 체험은 참고 리포 [javiow/sache](https://github.com/javiow/sache)의 채팅 UX
패턴(타이핑 인디케이터 + 메시지별 딜레이, 선택지 클릭 즉시 진행, 별도 전송/다음 버튼 없음)을
이식해 가해자-피해자가 실제 채팅하듯 대화가 이어지도록 재설계한다. 사례선택/전세매물은 기존
"선택 후 다음 버튼 클릭" 방식을 그대로 유지한다.
**이유**: 보이스피싱은 실시간 통화 상황을 다루므로 채팅형 UI가 몰입감·긴장감을 훨씬 잘
전달한다. 사례선택/전세매물은 두 대상을 나란히 비교하는 단발성 A/B 선택이라 채팅형으로 바꿀
이유가 없다.
**트레이드오프**: 3개 체험 유형의 인터랙션 패턴이 통일되지 않는다 — 다만 유형을 사전에
노출하지 않는 제품 특성상 사용자가 이 비일관성을 직접 비교해 체감할 일은 없다.
`ExperienceModule`/`ExperienceComponentProps` 계약(`content` prop, 단일 `onComplete` 호출)은
그대로 유지되므로 오케스트레이션 코드에는 영향 없다.
```

### 2. `docs/PRD.md`

- 핵심 기능 §1 랜딩 규칙 문구를 수정한다: `규칙(총 3단계 · 선택 후 "다음" 클릭 · 결과는 마지막에 공개)` → `규칙(총 3단계 · 선택하면 진행됨 · 결과는 마지막에 공개)`
- 핵심 기능 §2를 수정한다: `선택 직후 정답/오답 피드백 없이, 사용자가 "다음"을 눌러야 다음 단계로 진행.` → `선택 직후 정답/오답 피드백 없이 다음 단계로 진행한다. 사례선택/전세매물은 선택 후 "다음" 버튼을 눌러야 진행되고, 보이스피싱은 채팅형 UI로 선택지를 클릭하면 즉시 대화가 이어진다.`
- 핵심 기능 §3 보이스피싱 항목을 수정한다: `보이스피싱 — 선택지 기반 분기 대화. 사기 시나리오 사이에 정상 케이스도 섞여 있으며, 사기 케이스 거절은 정답, 정상 케이스 거절은 오답으로 채점("무조건 거절" 패널티).` → `보이스피싱 — 채팅형 분기 대화(가해자/피해자가 말풍선을 주고받는 방식, 타이핑 인디케이터 연출, 선택지 클릭 즉시 진행). 콘텐츠 풀은 "사기같은 정상 케이스" 2개 + "정상같은 사기 케이스" 2개로 구성해 표면적 인상과 실제 정답이 어긋나도록 설계한다. 사기 시나리오를 거절하면 정답, 정상 시나리오를 거절하면 오답("무조건 거절" 패널티), 사기 시나리오에 응하면 오답("사기에 넘어감" 패널티)으로 채점.`

### 3. `docs/ARCHITECTURE.md`

- 디렉토리 구조 주석을 수정한다: `# VoicePhishingExperience, CaseSelectExperience, JeonseExperience` → `# VoicePhishingExperience(+ChatBubble/TypingIndicator/ChatChoiceButtons), CaseSelectExperience, JeonseExperience`
- 데이터 흐름 절의 다음 줄을 수정한다: `→ 사용자가 선택 → "다음" 버튼 활성화 → 사용자가 "다음" 클릭 시에만 다음 단계로 (자동 전환/즉시 피드백 없음)` → `→ 사용자가 선택 → 사례선택/전세매물은 "다음" 버튼 클릭 시, 보이스피싱은 채팅형 UI로 선택 즉시 다음 대사/단계로 진행 (자동 전환/즉시 피드백 없음은 공통)`
- 엣지 케이스 절의 `"다음" 버튼은 클릭 후 다음 화면으로 전환되기 전까지 비활성화해 중복 클릭으로 ModuleResult가 두 번 쌓이는 것을 막는다.` 문장 뒤에 이어서 추가한다: `(보이스피싱의 채팅 선택지는 "다음" 버튼이 없는 대신, 선택지 클릭 시 즉시 잠금 처리해 동일한 중복 클릭 방지를 보장한다.)`
- 엣지 케이스 절에 새 항목을 추가한다: `보이스피싱 오답은 원인에 따라 두 가지 mistakeTag로 구분한다 — 정상 케이스를 거절: blind-refusal, 사기 케이스에 응함: fell-for-scam.`

### 4. `docs/UI_GUIDE.md` 삭제

이 문서는 더 이상 유지하지 않기로 했다 (사용자 결정). `docs/UI_GUIDE.md` 파일을 삭제하고, 이 파일을 참조하는 살아있는 문서의 링크를 정리한다:

- `docs/PRD.md`의 "디자인" 절: `다크모드 고정, 미니멀. anti-AI-slop 원칙 준수(\`docs/UI_GUIDE.md\` 참고).` → `다크모드 고정, 미니멀. 장식적 그라데이션/블러 글로우/보라색 브랜드 컬러 등 AI 템플릿 티가 나는 장식은 지양한다.` (문서 삭제로 참고 링크만 사라지는 것이지, "미니멀 anti-slop" 원칙 자체를 없애는 것은 아니다 — 문장으로 남겨 의도를 보존한다.)

`phases/0-mvp/step*.md`(이미 완료된 과거 phase의 실행 기록)와 `tests/browsing/*.js`의 주석에 남아있는 `UI_GUIDE.md` 언급은 과거 기록이므로 건드리지 않는다.
