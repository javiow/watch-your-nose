# Step 0: docs-update

## 읽어야 할 파일

먼저 아래 파일들을 읽고 프로젝트의 아키텍처와 설계 의도를 파악하라:

- `/CLAUDE.md`
- `/docs/PRD.md`
- `/docs/ARCHITECTURE.md`
- `/docs/ADR.md` (특히 ADR-003, ADR-007, ADR-009 — 세션 상태 원칙, 기존 유형 교체 선례, 4번째 유형 흡수 선례)

이 step은 문서만 다룬다. `src/` 코드는 이 step에서 전혀 건드리지 않는다(타입/데이터/스코어링/컴포넌트는 step1~3에서 다룬다).

## 배경

팀원이 별도 레포([`dakyommii/red-flag`](https://github.com/dakyommii/red-flag))에서 부동산 사기 추리 게임을 만들었다. 전세 3종·청약 1종·분양 1종·복합 파이널 1종, 총 6개 케이스로 구성되며, 사용자가 조사 포인트를 소모해 문서(등기부·시세·중개사 대응 등)를 열람하고 수상한 부분을 증거로 등록하고, NPC(중개사/상담사/가족 등)와 대화하며 발언과 증거 사이의 모순을 찾은 뒤, 마지막에 "계약 진행 가능/추가 확인 필요/계약 중단" 중 하나로 최종 판단하면 rule-based로 채점된 리포트를 보는 구조다. 원작은 FastAPI 백엔드 + LLM 기반 NPC 자유대화가 있는 풀스택 앱이지만, 채점 로직(`scoring.py`) 자체는 "게임의 정답은 LLM에 맡기지 않는다"는 원작의 명시적 설계 원칙에 따라 이미 순수 rule-based다.

이 콘텐츠를 기존 3번째 체험 유형 "사례 선택"(`typeId: "case-select"`, 사기/정상 사례 쌍 중 사기 쪽을 고르는 카드 비교형)을 완전히 대체하는 새 유형(`typeId: "case-investigation"`)으로 이식하기로 했다. `case-select`는 삭제한다. 원작 그대로는 아니고, 이 프로젝트의 기존 원칙과 백엔드 미사용 제약에 맞춰 다음과 같이 조정한다:

- **백엔드/LLM 전면 제거**: NPC 자유대화는 케이스별로 미리 정해진 질문 버튼(원작 `suggested_questions` 중 대사와 매칭되는 것만 채택) → 클릭 시 고정 대사가 나오는 방식으로 대체한다. 채점(`scoring.py`)은 그대로 TS로 재구현한다(위험신호 발견 40 + 증거 품질 20 + 모순 15 + 조사 효율 10 + 최종판단 점수, 합을 0~100으로 clamp).
- **조사 포인트/비용 시스템 유지**: 문서마다 비용이 있고, 초기 포인트 내에서 선택적으로 조사한다. 일부 조사는 다른 조사 완료(또는 특정 증거 등록)가 언락 조건이다.
- **모순 발견 단순화**: 원작의 드래그 연결 UI는 만들지 않는다. 사용자가 관련 NPC 질문을 클릭 + 관련 증거를 등록하면 자동으로 모순 점수를 획득한다. 학습 효과 보전을 위해 모순 설명은 `/result`에서만 노출한다.
- **최종 판단 3지선다 유지**: 원작 그대로 "계약 진행 가능/추가 확인 필요/계약 중단" 3지선다이며, 케이스별로 최고점 선택지가 다르다 — "최고점이 항상 '사기다'는 아니다"라는 원작의 교육 철학을 보존한다(예: 위험 신호가 경미한 케이스는 "진행 가능"이 최고점).
- **시간제한 미구현**: 원작의 `time_limit_seconds` 카운트다운은 만들지 않는다. 세션 상태를 가볍게 유지한다는 ADR-003 원칙과 맞으며, 시나리오 텍스트("20분 안에" 등)로만 서사적으로 유지한다.
- **케이스 제목 비노출**: 원작 케이스 제목(예: "위험한 전세가율")은 그 자체로 정답을 암시하는 스포일러다. `FraudJudgmentCategory`(ADR-009)와 동일하게 "렌더링 금지, 내부 식별용" 메타데이터로 취급하고, 체험 중 헤딩은 매물 위치 설명으로 대체한다.

## 작업

아래 3개 문서를 정확히 다음 내용으로 수정한다. 명시된 변경만 반영하라 — 이 문서들은 팀원 여러 명이 참조하는 합의된 설계 기록이다.

### 1. `docs/ADR.md` — ADR-009 뒤에 새 항목 추가

```markdown

### ADR-010: "사례 선택"을 팀원 제작 부동산 사기 조사 게임(red-flag)의 6개 케이스로 교체
**결정**: 기존 2択 카드 비교형 "사례 선택"(`typeId: "case-select"`) 체험을 팀원 레포([dakyommii/red-flag](https://github.com/dakyommii/red-flag))의 부동산 사기 추리 게임에서 이식한 콘텐츠로 완전히 교체한다(`typeId: "case-investigation"`). 원작은 FastAPI 백엔드 + LLM 기반 NPC 자유대화가 있는 풀스택 앱(전세 3종·청약 1종·분양 1종·복합 파이널 1종, 총 6개 케이스)이지만, 이 프로젝트는 백엔드/LLM 호출이 전면 금지이므로 다음과 같이 단순화해 이식한다: (1) 채점(`scoring.py`)은 이미 순수 rule-based(LLM 미사용)라 그대로 TS로 재구현한다(위험신호 발견 40 + 증거 품질 20 + 모순 15 + 조사 효율 10 + 최종판단 점수, 합을 0~100으로 clamp). (2) NPC 자유대화는 케이스별 고정 질문 버튼(원작 `suggested_questions` 중 대사와 매칭되는 것만 채택) → 클릭 시 고정 대사 노출로 대체한다. (3) 조사 포인트/비용 시스템(문서마다 비용 소모, 일부는 다른 조사 완료·증거 등록이 언락 조건)은 그대로 유지한다. (4) 원작의 드래그 연결형 모순 발견 UI는 만들지 않고, "관련 질문을 클릭 + 관련 증거를 등록"하면 자동으로 모순 점수를 획득하는 방식으로 단순화한다. (5) 최종 판단은 원작 그대로 3지선다(계약 진행 가능/추가 확인 필요/계약 중단)를 유지한다 — 케이스별로 최고점 선택지가 다르다. (6) 시간제한(`time_limit_seconds`) 카운트다운은 구현하지 않는다 — ADR-003 원칙과 맞고, 시나리오 텍스트로만 서사적으로 유지한다.
**이유**: 팀원이 이미 리서치·검증한 콘텐츠(실제 전세사기·청약사기·분양사기 사례 기반 6개 케이스)를 활용하면서, "정답은 LLM이 아니라 rule-based로 결정한다"는 원작의 설계 철학이 이 프로젝트의 백엔드 미사용 원칙(ADR-002)과 자연히 맞아떨어진다.
**트레이드오프**: 원작의 LLM 자유대화·모순 연결 UI·타이머 긴장감은 포기한다. 4개 체험 유형 중 상태가 가장 복잡한 유형이 된다(포인트·언락·증거등록·NPC 대화·3지선다를 한 컴포넌트가 관리) — 다만 영속화 계층 없이 단일 컴포넌트의 `useState`로만 구성해 ADR-003 원칙은 그대로 지킨다.
```

```markdown
- 케이스 조사는 조사 포인트가 부족하거나 언락 조건이 충족되지 않은 조사 항목을 비활성화/비노출하며, 부분 조사만 하고 최종 판단으로 넘어가는 것도 허용한다(원작과 동일한 UX).
- 케이스 조사의 모순 발견은 자동 판정이다 — 관련 NPC 질문을 클릭하고 관련 증거를 등록하면 자동으로 모순 점수를 획득하며, 모순 설명은 `/result`에서만 노출한다.
- 케이스 조사의 `isCorrect`는 점수 임계치가 아니라 "사용자가 고른 최종 판단이 해당 케이스의 최고점 선택지와 일치하는가"로 정의한다 — 케이스에 따라 "진행 가능"이 최고점일 수 있다(원작의 교육 철학 보존).
- 케이스 조사 오답은 두 가지 mistakeTag로 구분한다 — 최고점이 "진행 가능"인 케이스를 과도하게 의심해 오답 처리된 경우: `false-alarmed-safe-case`(기존 재사용), 그 외 위험 신호를 놓친 경우: `missed-realestate-investigation-signal`(신규).
- 케이스 조사 진행 중에는 케이스 제목(스포일러성 문구)·최종판단 코멘트·정답 해설을 화면에 렌더링하지 않는다 — 헤딩은 매물/상황 위치 설명을 대신 쓴다.
- 케이스 조사는 원작의 시간제한(`time_limit_seconds`) 카운트다운을 구현하지 않는다 — 시나리오 텍스트로만 서사적으로 유지한다.
```
