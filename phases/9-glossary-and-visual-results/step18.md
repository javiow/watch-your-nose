# Step 18: how-it-works-icon-steps

## 읽어야 할 파일

먼저 아래 파일들을 읽고 프로젝트의 아키텍처와 설계 의도를 파악하라:

- `/CLAUDE.md`
- `/docs/ADR.md`의 ADR-004(유형 사전 비노출), ADR-016
- `/src/app/how-it-works/page.tsx` (전체)
- `/src/app/how-it-works/page.test.tsx` (전체) — 특히 유형명 비노출 검증 테스트

## 배경

`/how-it-works` 페이지의 안내가 문장 위주라 읽기 부담스럽다("텍스트가 많다" 피드백). "무엇을 배우는지"를 문장 대신 아이콘 + 짧은 명사구 스텝으로 바꾼다. 유형명(보이스피싱/케이스 조사/전세매물/사기 판별)은 여전히 어디에도 노출하지 않는다.

## 작업

### `src/app/how-it-works/page.tsx`

- 상단 소개 문단이 2문장이면 1문장으로 줄인다.
- "무엇을 배우는지"를 설명하는 부분(현재 문장형이라면)을 아이콘 3개 스텝으로 교체한다. 예:
  - 🔍 위험 신호 포착
  - 📑 서류·정보 비교
  - 🤔 판단 연습
  아이콘은 `aria-hidden`, 그 옆/아래 짧은 명사구. 가로 배치(모바일에서 줄바꿈 허용).
- 기존 "진행 방식" 안내(여러 단계로 진행 / "다음으로 넘어가기" 버튼 / 즉시 피드백 없음 / 결과는 마지막에)는 유지하되, 각 항목의 문장을 조사·수식어를 덜어 더 짧게 다듬는다. 구조(불릿 목록)는 유지해도 된다.
- CTA 링크(`<Link href="/setup">`)는 그대로 둔다.
- 서버 컴포넌트를 유지한다(`"use client"` 붙이지 마라). 아이콘은 이모지 텍스트면 충분하다.

### `src/app/how-it-works/page.test.tsx`

- 유형명 비노출 테스트(`/보이스피싱|케이스 조사|전세매물|사기 판별/`가 안 나온다)는 그대로 유지되고 통과해야 한다.
- 신규/갱신: 아이콘 스텝의 명사구(예: "위험 신호 포착", "서류·정보 비교", "판단 연습")가 렌더된다.
- CTA 링크 `href`가 여전히 `"/setup"`이다.

## Acceptance Criteria

npm run build

## 검증 절차

1. 위 AC 커맨드를 실행한다.
2. 체크리스트:
   - 페이지 어디에도 4개 유형의 구체적 이름이 없는가? (부분 문자열 포함)
   - `"use client"`를 붙이지 않았는가?
   - `npm run dev`로 `/how-it-works`를 열어 스텝 아이콘이 보이고 모바일 폭에서 깨지지 않는지 확인했는가?
3. 결과에 따라 `phases/9-glossary-and-visual-results/index.json`의 `step: 18`을 업데이트한다:
   - 성공 → `"status": "completed"`, `"summary": "산출물 한 줄 요약"`
   - 수정 3회 시도 후에도 실패 → `"status": "error"`, `"error_message": "구체적 에러 내용"`
   - 사용자 개입 필요 → `"status": "blocked"`, `"blocked_reason": "구체적 사유"` 후 즉시 중단

## 금지사항

- 아이콘 스텝 문구에 유형명(보이스피싱/케이스 조사/전세매물/사기 판별)을 쓰지 마라. 이유: ADR-004.
- `"use client"`를 붙이지 마라. 이유: 이 페이지는 서버 컴포넌트로 충분하다.
- `src/app/setup/page.tsx` 등 다른 페이지를 건드리지 마라.
- 기존 테스트를 (갱신이 명시된 `how-it-works/page.test.tsx` 외에는) 깨뜨리지 마라.
